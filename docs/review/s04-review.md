# s04 复盘：Subagent

## 大白话讲

任务太大、太杂时，一个实习生从头干到尾，脑子（上下文）会被一堆中间细节塞满。

s04 的办法是：让主实习生当"组长"，遇到一块能独立干的活，就**叫个新实习生（子 agent）**过来，跟他说"你去把这件事办了，办完告诉我结论就行"。

关键点在于这个新实习生是**全新的脑子**：

> 子 agent 有自己独立的 `messages[]`，看不到组长的对话历史。组长也只拿回子 agent 的最终结论，不会被一堆执行细节污染。

这就是"干净上下文"——脏活累活的过程留在子 agent 那边，主 agent 只接收一份干净的摘要。

两个细节：

- **子 agent 不能再叫子 agent**：它的工具集里没有 `delegate`，防止无限套娃（孙子、曾孙……）。
- **可视化区分**：主 agent 的工具调用是黄色，子 agent 的是灰色 + 缩进，一眼看出谁在干活。回调是用模块级变量 `set_subagent_callback` 传进去的。

## 如果我是面试官

### 第一轮：确认你懂本质

**Q1：subagent 到底解决了什么问题？多一个 agent 不是更费 token 吗？**

> 它解决的是"上下文污染"。一个大任务里很多中间步骤（读了一堆文件、试了几条命令）对最终决策没用，但会一直占着主上下文。把这块委托出去，子 agent 在自己的上下文里折腾，主 agent 只拿结论。它的价值不是"多个工具"，而是"多了一层上下文边界"。

### 第二轮：挖设计

**Q2：子 agent 的"干净上下文"具体是怎么实现的？**

> `delegate` 的 `run(task)` 里新建一个 `messages = [{"role":"user","content":task}]`，然后用这个全新列表启动一个嵌套的 `agent_loop`。因为是新列表，它根本拿不到主 agent 的历史。执行完从子 agent 的 messages 里倒序找最后一条文本回复返回给主 agent。

**Q3：我让主 agent 记住一个暗号，再让它 delegate 子 agent 说出这个暗号，子 agent 能说出来吗？**

> 取决于暗号有没有被写进 `task` 参数。如果主 agent 把暗号写进了 task，子 agent 能说；如果没写，子 agent 不可能知道，因为它看不到主对话。这恰好证明了上下文是隔离的——子 agent 只知道你 task 里告诉它的。

**Q4：怎么防止子 agent 再无限委托下去？**

> 子 agent 的工具集里不放 `delegate`，它根本没有这个工具可调。另外子 agent 的 max_turns 设得比主 agent 小，进一步防失控。

### 第三轮：边界

**Q5：你的 delegate 是并行的吗？**

> 不是。它是同步、深度优先的——主 agent 调一次 delegate 会一直阻塞到子 agent 跑完才继续。即使模型嘴上说"我并行委托了"，实际还是一个接一个。真正的并行要等后面后台任务那一课。

### 临场提示
最容易考的是"**干净上下文怎么实现**"和"**暗号测试说明了什么**"，记住核心是"新建 messages 列表"和"信息只能靠 task 显式传递"。
