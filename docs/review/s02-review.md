# s02 复盘：Multi-Tool

## 大白话讲

s01 那个实习生只有一双手（bash）。s02 是给他**多发几样工具**：一把"读文件的尺"（read_file）、一支"写文件的笔"（write_file）。

但这一课真正想让你体会的不是"工具变多了"，而是：

> 加一个工具，到底要改多少地方？答案是——只加一个 handler，循环一行不动。

你只要写好新工具的"说明书"（SCHEMA，告诉模型这工具叫啥、要什么参数）和"执行体"（`run()` 函数），再在 agent 的 handlers 表里登记一行，就接好了。这就是把 s01 的"解耦"设计真正用起来。

另外两个细节体现了"harness 要替模型把关"：

- **路径安全**：模型让你读 `../../etc/passwd` 怎么办？read_file/write_file 用 `resolve()` 把路径摊平，再用 `is_relative_to()` 检查是不是还在工作目录里，越界就拒绝。
- **输出截断**：读到一个 50MB 的文件，全塞进上下文会爆。所以工具输出统一截断到 5 万字符。

## 如果我是面试官

### 第一轮：确认你懂本质

**Q1：从 s01 到 s02，你的 `core/loop.py` 改了几行？为什么？**

> 一行没改。因为 s01 就把工具分发设计成了 handlers 字典，加工具只是往字典和工具列表里各加一项，循环逻辑跟"有哪些工具"完全无关。这是验证我那套解耦设计是否成立的第一课。

### 第二轮：挖设计

**Q2：一个工具在你这套架构里由哪几部分组成？**

> 两部分：`SCHEMA`（OpenAI function calling 格式的工具定义，给模型看的"说明书"）和 `run(**kwargs)`（真正干活的函数）。agent 入口再把 `SCHEMA` 加进 TOOLS、把 `run` 加进 HANDLERS。三处登记，工具就上线了。

**Q3：模型给你一个绝对路径要读文件，你怎么防止它读到工作目录外面？**

> 先 `Path(p).expanduser().resolve()` 把符号链接和 `..` 都解析成真实绝对路径，再用 `is_relative_to(工作目录)` 判断。解析后还在目录内才放行，否则返回错误。关键是要在 resolve 之后判断，不能在字符串层面判断，否则 `..` 能绕过去。

### 第三轮：边界

**Q4：为什么要截断工具输出？截断会不会丢信息？**

> 会丢，但不截断风险更大——一个超大文件能直接撑爆上下文窗口，导致后面所有调用都失败。截断是两害相权取其轻。更好的做法是分页读或者按需读片段，但在这一课，固定上限 5 万字符已经够用。

### 临场提示
这课的考点几乎都围绕"**加工具的成本**"和"**工具的安全边界**"，答题时多强调"循环没动"和"resolve 之后再校验"。
