# s05 学习笔记：Skills —— 用到什么知识，临时加载什么知识

## 这一课新加的机制

### 1. load_skill 工具（tools/skill.py）

让 agent 按需加载技能文件，获取专业领域知识。

核心思路：不把所有知识塞进系统提示词（浪费上下文窗口），而是模型自己判断需要什么知识，调用 `load_skill` 按需加载。技能内容作为工具输出返回，进入对话上下文。

设计要点：
- **技能 = markdown 文件**：`skills/` 目录下的 `.md` 文件，文件名即技能名
- **容错设计**：请求不存在的技能时，返回可用技能列表而非报错
- **路径安全**：`is_relative_to()` 防止通过 `../` 读取任意文件
- **自动发现**：`_list_skills()` 扫描目录，读取第一行作为简介

### 2. 技能目录（skills/）

三个示例技能，覆盖不同场景：
- `git.md`：版本控制操作规范
- `debug.md`：调试排查流程
- `refactor.md`：代码重构指南

### 3. 系统提示词中的技能引导

系统提示词告诉模型"什么时候该加载哪个技能"，作为使用的触发条件。模型不一定每次都遵守，但有了引导，使用率会高很多。

## 相比原版的三个差异

| 差异 | 原版 | 本项目 | 理由 |
|---|---|---|---|
| 技能格式 | JSON/YAML 结构化定义 | 纯 markdown 文件 | 写和维护都更简单，专注内容 |
| 工具设计 | 列出/加载分为两个工具 | 一个 load_skill 工具处理两种情况 | 减少工具数量，模型决策更简单 |
| 技能发现 | 注册表或硬编码列表 | 自动扫描 skills/ 目录 | 加新技能只需加文件，不用改代码 |

## 关键领悟

1. **Skills 本质上是"延迟加载的 system prompt 片段"**。系统提示词告诉模型"有这些能力"，模型在需要时才调用 load_skill 获取详细知识。这种分层设计比把所有知识都塞进 system prompt 更高效。

2. **容错比报错好**。请求不存在的技能时返回可用列表，模型可以从中选择正确的名称继续执行，而不是卡住。

3. **文件即技能，目录即注册表**。不需要数据库、不需要配置文件，`skills/` 目录下的 `.md` 文件就是全部。新加技能 = 新加文件，零代码改动。

4. **s04 + s05 叠加后的关键问题：子 agent 看不到主 agent 已加载的 skill。** 子 agent 是干净上下文，主 agent 加载的技能内容不会传递过去。解决方案有两个：(a) 主 agent 把技能要点写进 delegate 的 task 参数；(b) 给子 agent 也加上 load_skill 工具，让它自己按需加载。两种都做了。
